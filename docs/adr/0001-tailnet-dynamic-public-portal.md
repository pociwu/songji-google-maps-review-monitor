# ADR 0001：於監控主機提供 Tailnet 內的動態展示頁

## 狀態

已採用。

## 背景

監控程式已在 Ubuntu 主機上保存 SQLite 評論資料與評論附帶媒體。使用者需要依店家檢視監控狀況、評論與管理者維護的貼文、照片、影片，但不需要網站登入功能。

## 決策

在同一台 Ubuntu 監控主機執行動態 Python 網頁服務，直接讀取既有 SQLite 資料庫與媒體檔案。服務綁定 `0.0.0.0:8088`，由 Tailscale tailnet 提供網路存取；網站本身不實作登入。

應用程式即使可以讀取整個專案，也不得把整個專案當成靜態檔案根目錄。`/media` 只允許解析後位於 `data/media/` 或 `data/portal/`、不含隱藏路徑且副檔名列入圖片／影片白名單的實體檔案；其他路徑一律回傳 `404`，成功回應加入 `X-Content-Type-Options: nosniff`。

自 v0.7.1 起，首頁提供新增監控店家表單，沿用 Tailnet 存取邊界，不新增帳號登入。分享網址先經白名單 Google 網域逐跳解析，使用者確認店名與 Maps 預覽後，以同源 JSON 請求及有時效簽章預覽儲存。設定檔先備份，再以原子替換追加店家；既有 URL 不改寫，以保存原 shop_key。監控仍由原排程執行，表單不啟動 Chromium 或分析工作。

## 後果

- 監控完成後，網站可立即讀取並呈現最新資料，不需靜態網站建置流程。
- 網站與監控程式共用資料目錄，部署與備份須維持資料庫及媒體檔案的一致性。
- 存取邊界由 Tailscale 管理；`0.0.0.0` 只代表主機監聽所有網路介面，並非網際網路公開網址。
- 網站不另行處理使用者帳號、登入或權限角色。
- `.env`、`config.toml`、SQLite、YAML、除錯檔、備份及其他專案檔案不能透過媒體網址下載；新增素材必須放入既定媒體根目錄並使用允許的圖片／影片格式。
- Tailscale ACL 與 OCI 網路規則仍須限制可連入 8088 的對象；媒體白名單是必要的檔案層防護，不能取代網路層存取控制。
